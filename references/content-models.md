# Content models

The templates are only as good as the content inside them. This file gives you
the reusable content models, the Sogeti narrative, the proof rules and the
fictional scenario used across the reference set.

---

## 1. The first rule

**Real content beats generated content.** If the user gives you a brief, a
transcript, a client name, a metric or an approved quote, use it. Do not replace
it with a plausible invention. If a fact is missing, write around it or mark the
draft clearly; do not fill the gap with a statistic.

The second rule: **no lorem ipsum**. Placeholder Latin is a tell that the
artifact was generated from a template, not from the work. Use a real sentence
structure with a bracketed unknown only in a working draft.

## 2. The Sogeti narrative

Use these as source material, not as copy-paste blocks.

**Proposition.** At Sogeti, we believe in making value. We help organizations
take full advantage of technology opportunities and deliver viable outcomes at
speed.

**Narrative.** Disruption is the norm. How quickly an organization responds
determines its future success, and the ability of IT to realize rapid value is
crucial. Sogeti calls this **value in the making**. It requires a trusted,
hands-on partner from day one: agile, innovative and close to the client, with
global scale behind it. We put the customer at the heart of the business. We
live and breathe technology, complementing a culture of **making IT work** with
deep knowledge of existing and emerging technologies.

**Brand line.** *The magic is in the making.*

**Proof of scale.** Sogeti is part of the Capgemini Group. Use the current
approved boilerplate for employee count, countries and revenue; the figures in
the 2024 PDF are from 2023 and should not be copied into a 2026 artifact without
checking. If you do not have the current numbers, describe the model (“local
teams, global scale”) rather than quoting an old figure.

**Service lines.** Quality engineering, cloud and application development,
digital product engineering, data and AI, cybersecurity, intelligent
automation, delivered through a DevOps approach. Only claim what the engagement
can staff.

## 3. The Northline scenario

The reference templates use a fictional client so the set feels coherent without
pretending to be a real case. It is **illustrative** and labelled as such.

| Field | Detail |
|---|---|
| Client | Northline Group |
| Sector | European insurance |
| Size | 4,200 people, six markets |
| HQ | Amsterdam |
| Program | Claims platform modernization, phase 2 |
| First slice | First-notice-of-loss intake, one product line |
| Decision owner | Chief Claims Officer |
| Other roles | COO, CTO, CPO, Head of Claims Ops, Solution lead, Client partner |
| Discovery | 5–6 November 2026 |
| Steerco | 14 November 2026 |
| Decision needed | 21 November 2026 |
| Live proof | Four weeks, ending at the week 12 gate |
| Outcomes | 9→3 days intake; 41→70% straight-through; 14→5 touches; €38→€24 per claim |
| Event | The handover gap, 4 March 2027, Amsterdam |

**Rules for the scenario:**

- Keep the numbers consistent across templates.
- Label it “illustrative” in the footer, the method note or the source line.
- Do not present the outcomes as Sogeti's general results.
- Replace the entire scenario with the client's approved facts before external
  use.
- Do not add a real client logo or a real person's name to the scenario.

## 4. Page jobs

Every artifact has one job. Write it down before the layout.

| Artifact | Job | Reader's question |
|---|---|---|
| Insight article | Change a belief | “What should I think about this?” |
| Pursuit one-pager | Win a decision to explore | “Is this worth a meeting?” |
| Steerco | Get three decisions | “What do you need from me?” |
| Architecture | Approve a boundary | “What changes, and what stays?” |
| Workshop synthesis | Turn talk into decisions | “What did we agree?” |
| Maturity assessment | Start an evidence conversation | “Where are we, really?” |
| Options appraisal | Expose the weighting | “Which option, and why?” |
| Case study | Make the outcome credible | “Did it work, and would it work for us?” |
| Event page | Fill the room with the right people | “Is this for me, and how do I join?” |
| Playbook | Turn a method into action | “What do I do next?” |
| Data story | Make a finding legible | “What does the data say?” |
| Deck | Land an argument in 20 minutes | “What is the decision?” |
| Decision brief | Record a decision | “What am I signing?” |
| Slop audit | Gate a design | “Would this ship?” |

If the page cannot answer the reader's question in the first screen, the layout
is not the problem. The content is.

## 5. Page structures

### Insight article
Kicker → display claim → dek → meta → opening → argument (3–5 sections) →
figure → evidence table → quote → close → CTA → summary export.

### Pursuit one-pager
Cover (client, date, decision requested) → brief grid (opportunity / ask /
commitment) → situation → what we heard → approach → value case → why Sogeti →
team and governance → next 30 days → decision and sign-off.

### Steerco
Opener (status statement) → RAG strip → decisions required → delivery
confidence chart → milestones → risks → actions → what changes if we decide →
next meeting.

### Architecture
Opener (pattern statement) → current/target tabs → legend and annotations →
design decisions (ADR table) → what we are not doing → risks → cutover rules →
decision.

### Workshop synthesis
Opener (what/why/how) → method brief → selectable themes (quote, meaning,
decision) → unresolved tension → decision register → actions → next workshop.

### Maturity assessment
Opener (what it is / is not) → eight dimensions → live radar → table fallback →
three moves → how to use it → export.

### Options appraisal
Opener (the weighting is the argument) → weight profiles → matrix → live
results → recommendation → what the model does not capture → decision record.

### Case study
Dark opener (outcome + one number) → stat strip → challenge → approach →
figure → outcomes table → quote → what we would do differently → CTA.

### Event page
Opener (title, date, venue, invitation) → event card → why this summit →
agenda → speakers (roles) → practical details → request invitation → ICS.

### Playbook
Opener (what it is, 20 checks) → progress rail → five chapters with checks and
field notes → decision gate → personal plan export.

### Data story
Data opener (finding + one number) → stat strip → two charts → what it means →
method and limits → caveat → next question.

### Deck
Cover → premise → model → evidence test → where it breaks → proof → proposal →
decision. Eight slides; one idea per slide.

### Decision brief
Letterhead → title → decision box → context → options → recommendation →
conditions → risks → decision record → sign-off.

### Slop audit
Opener (the gate) → four tiers → live verdict → copy audit → false positives.

## 6. Headline bank

Use one per page. Do not string them together.

- The demo is solved. The handover is not.
- A shorter path from legacy to live.
- Confidence is up. Capacity is the constraint.
- One event seam. Two release paths. No big-bang cutover.
- What we heard, what it means, what we decided.
- Where does AI delivery actually stand?
- The weighting is the argument.
- From nine days to three. Without stopping the book.
- Would this page pass?
- The queue is the product.
- Who owns the model on the Monday after go-live?

Every headline should pass the logo-swap test. If a competitor could use it
unchanged, it is not saying anything.

## 7. CTA bank

- Book a working session
- Bring us the handover
- Request an invitation
- Read the field note
- Copy the decision record
- Print or save as PDF
- Add to calendar
- Talk to the claims team
- Discuss the proposal
- Review the architecture
- Copy the summary
- Copy my plan

Every interactive artifact ends with an export or a next action. A page that
ends in a dead end is a document, not a tool.

## 8. Quote and proof rules

- A quote needs a name, a role, an organization and written approval. If it is
  a composite, say so next to the quote.
- A statistic needs a source, a date and a base. If it is illustrative, say so.
- A client logo needs permission. A logo wall without permission is a legal and
  ethical risk.
- A certification or award needs a current certificate. Do not imply one.
- A number without a unit, a period or a baseline is a decoration.
- An “industry average” needs a named study. If you cannot name it, do not use it.

The templates use visible notes: “illustrative scenario”, “composite quote for
layout reference”, “planning assumptions, not commitments”. Copy that discipline
into real work, then replace the note with the approved fact.

---

## 9. Content checklist

- [ ] The page has one job and one reader.
- [ ] The first screen answers the reader's question.
- [ ] Every section earns its place; no section exists only to fill a grid.
- [ ] Every number has a source or an illustrative label.
- [ ] Every quote is approved or labelled composite.
- [ ] Every client name is approved.
- [ ] The headline passes the logo-swap test.
- [ ] There is no lorem ipsum.
- [ ] The CTA describes the next step.
- [ ] The export produces something a reader can paste into a decision record.
